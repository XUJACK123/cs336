# GPU
- CPU针对的是低延迟的优化，而GPU针对的是吞吐量的优化
- 访问的权限：
1. pre-thread:寄存器，局部内存
2. pre-block:共享内存(shared memory)
3. pre-grid:全局内存(global memory)
*** 注意：CPU只能读写GPU的global memory和constant memory
- TPU：结构和GPU类似，区别在于TPU是包含了MXU/VPU之类的由向量组成的东西，GPU是使用通用并行设计，有强大的多线程并行的能力，而TPU是为矩阵计算设计的，不需要频繁的读写寄存器

## 如何让GPU运算变快：
- 用roofline模型定义算术强度，区分任务是受限于内存还是算力
1. 避免控制歧化，让warp中的线程在同一时刻必须执行相同的任务，例如如果出现奇偶线程分叉，把if (threadIdx.x % 2 == 0)改为if (threadIdx.x / 32 < 1)，这样能够使得前32个线程走分支1，后面32个线程走分支2，使得能够充分利用GPU
2. 使用低精度的数据计算，使用FP16的数据相乘，使用FP32累加器相加
3. 算子的融合以减少内存的读写，在寄存器中连续完成所有的步骤，最后再将结果写回到DRAM(global memory)中，例如计算：$\sin^2(x) + \cos^2(x)$，如果是传统的需要五次的往返搬运(sin, cos, pow, add)但是使用编译技术能用编译器将其变为统一的CUDA Kernal，减少中间的搬运
4. 传统做法是从DRAM中读取x，然后算出来的中间结果a1,a2,a3写回DRAM中，这会导致需要不停的读写和传送，采用重计算能够连续算完之后一次性直接存最后的结果a3，在反向传播的时候重新计算a1和a2，减少传送的时间和次数
5. DRAM读取是一整块的读取，如果在访问DRAM的时候访问的东西的地址是离散的，会产生多次的独立请求，浪费时间，而我们可以把要用到的数据先放在同一个块之中然后一次性直接读取
