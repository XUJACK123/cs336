# inference
## 对于运行速度快慢的定义
- time-to-first-token：响应时间多长，从用户发送请求到模型吐出第一个 token 的等待时间
- latency：生成token的延迟，生成单个 token 所消耗的平均时间
- throughout：系统在单位时间内(针对多请求并发或批处理)总共能够生成的token总数，但是有些时候会希望吞吐量大点更好

## 减少 KV Cache 显存占用：
- 自回归大语言模型的推理加速的核心技术，使用显存空间换取计算时间
- 新的token只需要计算自己的QKV然后将KV拼接到KVCache中与历史缓存的K和V进行点积计算
1. 使用GQA/MQA，让多个Q头共享同一组的key/value
2. 显存中没有完整的key/value，只需要存储极小维度的压缩量
3. 设置一个固定长度的W的滑动窗口，保留W个token，丢弃更早的历史

## 模型量化：
- 将FP16/BF16权重量化为INT8/INT4/FP8/FP4，然后直接由显存中读取，将数据量减少2-4倍

## 模型剪枝和蒸馏：
- 裁剪多余的网络层/通道/使用大模型指导小模型->缩小模型的体积
- 如何知道哪些网络通道是没有用的呢：
    1. 看权重的绝对值大小，权重参数接近0代表几乎不起作用，利用batch normalization的缩放因子 $\gamma$，对缩放因子 $\gamma$ 实施稀疏惩罚，结束后把趋近于0的裁掉
    2. 看loss的灵敏度，如果假装把某个通道设为 0 后，模型预测结果和Loss几乎没有任何波动，说明模型对该通道不敏感，可以安全裁剪
- 剪枝为什么不会影响整体，因为减去A层的同时上下的B/C层都会相对应的减去对于的东西

## 使用lossless acceleration：
- 用一个极快的小模型预测了K个token，然后将K给token变为一个batch喂给大模型并进行一次性验证
- 只要大模型输出概率和预测的一样就输出。这种方法只需要让模型跑一次前向传播，一次前向传播能预测K个字，如果小模型预先给出了K个候选字，大模型能直接并行算出这5个字的位置概率分布
- 大模型相当于是先默认小模型的预测是对的然后同时预测这5个位置，如果中间有不对就重新一个一个预测

## Continuous batching
- 静态批处理：如果一个batch中有4个请求，请求A可能是需要生成10个token，请求B是生成500个token，这会导致A需要等到B跑完才能统一返回
- 连续批处理：把处理的精度变为token步，相当于是每次请求的东西都是token，只要有请求生成完毕(遇到结束符)，立刻踢出 Batch 并释放显存返回结果，让GPU时刻保持满载的状态

## pagedattention
- 传统KVCache：在transformer中每个请求的KVCache随字数增长而增长，系统会先划分一个连续的CPU显存，但是很多时候会出现浪费
- vLLM使用了操作系统的CPU内存管理，将KVCache拆分，通过维护一张页表将连续的token变为分散的内存中
